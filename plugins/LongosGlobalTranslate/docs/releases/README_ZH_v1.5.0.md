# LONGOS 全球翻译 v1.5.0 — 运营实用性、增量翻译和发布指南

> 本次版本侧重解决“上传了新版 ZIP，但是前端仍然是旧脚本”和“新语言没有保存却创建任务失败”的实际问题。

## 重要：LONGOS 本身采用 Git/Coolify 镜像发布

公开主仓库的 `plugins/LongosGlobalTranslate/config.json` 目前仍是 v1.3.1。仅通过后台上传 ZIP 覆盖运行中容器，可能遇到应用代码未升级、静态脚本尚未发布，以及容器重建后回退的问题。推荐：将压缩包中的 `LongosGlobalTranslate` 完整覆盖到 LONGOS 源码仓库的 `plugins/LongosGlobalTranslate`，提交到部署分支，走现有 Coolify Git 构建发布流程；发布前备份站点数据库及原插件。请勿在生产容器中直接执行破坏性数据库迁移。

发布后，后台「运行环境自检」会显示插件 manifest 的真实版本，以及 `Static/public/widget.js` 和 `public/plugin/longos_global_translate/widget.js` 内容是否相同。不同则需检查 LONGOS 的静态资源发布步骤。


## v1.5.0 运营功能更新

1. **增量扫描、增量建库**：扫描仍只索引许可公开原文；仅对缺失或因原文变更失效的译文新增队列项。已有同原文哈希的有效译文自动复用，人工锁定译文不被机器覆盖。反复点击创建任务不会重复添加相同任务项；无新增内容会产生一个不派发 API 的已完成记录。
2. **每种语言的可用度状态**：工作台可查看该语言原文索引总量、有效译文、待审核、已审核、当前已发布数及下一步操作建议。统计是数据库索引层级的状态，不保证每个具体页面均可展示。
3. **翻译库可检索**：按目标语言、审核状态、内容类型、英文原文或译文关键词过滤；按页加载，每页 25 项。审核和手动修改后可刷新当前筛选结果。
4. **品牌与型号保护词**：在翻译库内展开“品牌／型号保护词”，为未来机器翻译加入原样保留的术语，如 `NYBGBAR`、`iPhone 16 Pro`。最多 200 条，每条只影响下一次新翻译请求；历史译文不会静默改变。
5. **重复发布不再生成相同快照**：若当前已发布词典和待发布的完整版本、原文哈希与文本都一致，直接返回当前版本，不再制造无意义的历史版本。若任何译文修订或内容范围发生变化，仍产生新版本，保留回滚能力。
6. **更清楚的后台交互**：语言勾选和快捷发布列表同步，建库前自动保存当前语言配置，任务通知显示新增条目／复用译文／需人工处理数量；实时状态轮询周期调整为 15 秒。
7. **保持安全边界**：不开启未经验证的付费额度；公开页面不执行翻译计费请求；多租户数据库分离、加密凭据、审计和人工锁定规则不改变。

### 最短运营流程（适合日常补充商品）

- **首次配置**：设置语言 → 保存并验证服务商凭据 → 在确认免费额度后授权派发 → 点击「扫描并创建翻译任务」→ 等待任务完成 → 抽查／审核译文 → 发布 → 开启前端语言选择器。
- **后续上新**：直接点击「扫描并创建翻译任务」；插件只为缺失或失效的译文规划新项。若统计显示 `新任务条目 0`，且发布词典没有更新必要，就不用重复调用 API。
- **检查故障**：优先打开后台「运行环境自检」，确认 v1.5.0、静态 JS 同步、已生成译文、已审核、已发布、选择器开启；再检查前端公开页面与接口返回。
- **保护术语**：先添加品牌词，再对新内容翻译。如果已有品牌被错误机器翻译，请在翻译库中人工修正、审核并重新发布；添加保护词不会自动改写旧译文。

### 发布前必须知道的限制

- `公开原文总量` 代表被允许的扫描索引，而不是全站所有文本；只支持公开的纯文本白名单，不翻译富文本 HTML 商品详情、任意页面脚本、用户输入或完整多语言 SEO。
- `可复用译文` 包含未人工审核的译文，不等于已发布；`当前已发布` 仍需目标页面存在可匹配字段和词典，页面级效果要实际打开验证。
- 快捷发布中的基础格式检查 **不等于语义审校**，涉及品牌、型号、材质、尺寸和售后政策时应人工抽样核对。
- 保护词上限为 200，保护范围为新发出的机器翻译任务；不提供自动扫描历史品牌遗漏或对所有网页内容强制替换的能力。
- 该包仅经过本地语法、模拟数据库和浏览器模拟检查，未在用户的 Coolify 生产实例、真实队列、MySQL 租户库及服务商账号中完成端到端验证。

## 新增的自检结果

- 当前运行版号：由实际服务器的 config.json 获取，不依赖用户手里的 ZIP 文件名；
- 静态脚本：比较本地插件 JS 与真正对外提供的 JS 文件哈希；
- 队列连接：列出 `queue.default`，但不将它当作 worker 存活证明；
- 逐条提示没有语言、没有原文、服务商未启用、待处理任务无进度、没有审核译文、未发布、前台开关关闭。

## 排障路径

1. 后台确认 **运行版号 v1.5.0** 和 **前端脚本已同步**；否则先修复部署，而不是反复创建翻译任务。
2. 勾选目标语言并保存，选择「仅免费额度」进行新翻译（仅已发布词典模式不发 API 请求）。
3. 保存服务商凭据，人工确认一次受控验证，再开启**明确的**免费额度派发授权；不要输入无法核实的额度值。
4. 「扫描并创建翻译任务」会先自动保存当前目标语言设置；查看任务是否达到 `completed`，而不只是 `queued`。
5. 等待实际生成译文，再批准合格结果，点击发布；发布的词典才是前端真正使用的数据。
6. 打开公开商品页，在 URL 中添加 `?lgt_debug=1`（原有 query 时用 `&lgt_debug=1`），浏览器控制台检查 `config-loaded` 的 `release: 1.5.0`、publishedLocales、applied。

## 适用范围边界

只处理白名单公开纯文本（产品名称、分类名称、页面标题、部分已发布 Builder 模块及明确的静态界面标签），不支持自动翻译所有第三方模块的富文本 HTML。前台无匹配词典的页面会保持英文，选择器不再错误显示仿佛整页已经翻译。

# LONGOS 全球翻译插件 v1.5.0 — 升级与操作说明

> 适用范围：上传的 LONGOS 插件包 `LongosGlobalTranslate(2).zip` 的原位修复。保留原目录名称 `LongosGlobalTranslate`，保持现有 `lgt_*` 表结构、已有翻译库、服务商账户与历史发布快照，不新增迁移。

## 一、最简单的上线步骤

1. **原位升级**：先备份插件目录和租户数据库。对于当前 LONGOS 的 Git/Coolify 镜像部署，推荐解压 ZIP 后将 `LongosGlobalTranslate` 目录提交到应用部署分支、通过 Coolify 正式构建发布；不要先卸载旧插件或删除任何 `lgt_*` 表。若使用后台上传 ZIP，仅解压不保证更新镜像或重新发布 `public/plugin` 静态资源，必须在运行环境自检中核对版本与脚本一致性，并按项目正常流程检查迁移/队列 worker。
2. **启用语言和模式**：进入「LONGOS 全球翻译工作台 → 语言策略」，勾选目标语言，并将模式改成 **仅免费额度（free_only）**，保存。如果只想使用已有发布词典而不再调用第三方 API，才使用「仅已发布词典」。
3. **配置 API**：在「服务商与额度」中添加阿里云/火山引擎/百度凭据，设置真实免费额度与本地安全上限，保存、验证，然后**明确开启派发**。验证请求本身可能产生计费；本地上限不等同服务商的硬性计费保证。建议同时在服务商控制台设置账单提醒/额度限制。
4. **创建翻译库**：进入「翻译库」，点击 **扫描并创建翻译任务**。此按钮已经自动完成公开内容扫描及任务规划，不必先单独点「扫描」。这一步只是创建任务，不代表翻译完成或已向前台发布。
5. **等待真实任务完成**：在「发布与前台」查看任务状态；「已完成」且出现译文才算完成翻译。长期排队/暂停应检查 worker、账户验证、派发开关和真实余额。不要因创建了任务就认为翻译成功。
6. **一键发布**：在「发布与前台」选择语言，点击 **审核合格译文并发布**。此操作只自动批准通过基础格式检查的机器译文；语义与品牌准确性仍须人工抽查。默认同时开启前台语言选择器。存在质量警告的译文留待人工审核，不会自动通过。
7. **验证前台**：打开一个确有原文的商品页 `/products/商品ID`，点击语言浮窗检查标题。首页、分类列表有相应的公开词典时可通过批量匹配展示；仍不匹配的字段需要在 LONGOS 页面模板中提供明确的 `data-lgt-*` 标记。

## 二、什么是“真正创建成功的翻译库”？

- **公开原文**：只证明扫描建立了索引，**不代表已翻译**。
- **已翻译**：后台存在机器结果或待审核结果，**不代表能够前台展示**。
- **已审核**：通过人工审核或本次新增的、管理员确认的基础检查自动批准。
- **已发布语言**：必须存在一份含有有效译文的不可变发布快照。
- **前台可见**：上一步完成后，后台语言选择器开关必须开启，当前页面还必须包含可匹配的公开原文。

后台首页现有「翻译库实际状态」可查看上述主要数量；其中「已发布」并不保证某个具体页面的每一段文字都能翻译。

## 三、v1.5.0 重点修复

- 兼容**没有** `data-lgt-root` / `data-lgt-field` 的部分主题页面：仅在允许的商品/分类/公开页面 ID、已发布 Builder 模块范围内对**已发布**词典的原文做精确文本匹配；不上传任意网页正文给翻译 API，不写入 HTML。
- 新增受限的 `dictionary/batch` 批量词典读取，最多 48 个公开实体/请求，显著减少商品列表及装修模块页面的请求数与限流风险；同时保留原单实体词典接口。
- 解决 Builder 60 位整数 ID 在 JS 使用 `Number()` 导致精度丢失，以及本地 HTTP 不支持 `crypto.subtle` 时标记模式不能翻译的问题。
- 前台语言切换支持回滚原文、动态节点处理和过期异步结果抑制；受保护的表单、交易、价格、支付、个人信息等区域不进入通用匹配。
- 空译文发布被拦截；快捷发布会留下独立 `auto_basic_check` 版本审计标记，异常结果不得绕过人工审核。
- 任务不因旧的 preview-only 规划记录阻塞新的免费额度任务；原文及译文哈希未变化时优先复用，不再次调用计费 API。锁定的人工译文不会因新的任务而被机器覆盖。
- 配置保存统一事务；修复「已发布版本」页面查询错误状态字段；简化后台操作与实时状态提示。

## 四、前台检查与诊断

打开 `https://你的站点/products/商品ID?lgt_debug=1`，浏览器开发者工具 Console 中查看 `[LONGOS Translate]` 提示。Network 应能看到：

- `/global-translate/config`：`enabled=true`、`published_locales` 中包含目标语言；
- `/global-translate/dictionary/batch?...`：返回 `dictionaries`，各实体包含 `items / fields / sources`；
- POST `/global-translate/locale`：手动切换需要 CSRF token / 有效会话；
- 真实 DOM 标记模式仍可走原有 `/global-translate/dictionary/{kind}/{entityId}`。

如果浮窗**完全不出现**：检查设置 `widget.enabled`、插件数据库结构、`Bootstrap` 中指定的 `layout.master.footer.code` 主题钩子是否执行、相关路由是否注册以及 `widget.js?v=1.5.0` 是否正确加载。若使用定制主题且没有该钩子，必须在主题中接入此插件，不应误判为翻译数据库的问题。

如果浮窗出现但**内容不翻译**：先看对应语言是否已发布有效词典，再核对原文是否改变、商品是否公开、当前页面是否有可识别的 URL/商品链接/Builder 模块、该字段是否在扫描允许范围内。开发者工具中请求 403/419/422/429/5xx 需分别排查会话、配置与限流、后端异常。

## 五、设计边界与注意事项

1. **源语言仍锁定 `en`**。原代码并未实现通用非英语源语言方案，本次为兼容旧库不更改此数据契约。
2. 默认允许的目录字段主要是**商品名称、分类名称、页面标题**；部分发布的 Builder 纯文本字段和有限的静态结账 UI 标签。复杂 HTML 商品描述、富文本、营销组件外的任意正文及完整多语言 SEO URL/SSR **仍不属于本次的安全覆盖范围**。
3. 批量智能匹配限制为最多 32 个页面内关联实体 + 16 个 Builder 模块，单次最多 48 个实体。其他大列表/无标记的复杂页面，应在 LONGOS 模板内增加 `data-lgt-*` 标记或分批加载。
4. 自动审核只有**格式与基础异常检测**，不能代替专业人工审校；品牌、尺寸、材质、保修/退款政策必须抽查后再发布。
5. 未在真实 LONGOS 实例、真实租户数据库、生产主题、队列进程及翻译厂商账号上执行集成测试。本包已通过本地语法、静态绑定与浏览器模拟回归，但**不能据此声称已在生产环境验证所有功能**。
