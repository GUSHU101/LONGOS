# LONGOS Global Translate v1.10.0 — 当前装修模块增量翻译

发布日期：2026-11-09

## 本次要求与范围

1. **不翻译 SEO 元数据**：Meta Title、Meta Description、Open Graph、Schema 及其他仅用于搜索引擎/页面头部的配置不进入翻译任务。
2. **只扫描当前租户已经发布且显示中的 Builder 装修模块**，不会遍历整个组件库、未发布草稿或被设置为 `visible=false` 的模块。
3. 当前模块新增或变更可见英文文字时，下次管理员点击 **「扫描并开始」** 或 **「创建安全翻译任务」**，先执行增量扫描，仅安排未翻译或原文变化的字段；原文没变的已翻译条目继续复用。
4. 删除、隐藏或移除模块后，下次扫描将旧 Builder 索引设为不可公开、已淘汰，不再生成该模块的新翻译任务。

> 本版本没有在每次前台访问时调用 AI，也没有借助访客浏览器把整个 DOM、表单或交易数据发到翻译接口。为了控制成本和避免隐私外泄，**新增模块发布后需要由管理员发起下一次扫描/任务**；在未取得 LONGOS 核心发布钩子的完整源码和测试环境前，不宣称已具备后台无感自动发布检测。

## 具体改动

| 位置 | 改动 |
| --- | --- |
| `Services/ContentScanner.php` | 保留已有组件字段白名单，增加对**已发布模块实际配置**中标题、字幕、说明、按钮、提示、FAQ、富文本等显示字段的递归发现；即使新模块代码尚未登记在静态白名单内，也可以通过安全字段规则被索引 |
| `ContentScanner::builderDisplayFields` | 新增公开文本候选发现器：处理嵌套集合、英文本地化字段、驼峰字段名和 HTML 文本节点；默认排除隐藏子项、URL、资源地址、SEO、样式、客户/订单/付款等敏感键 |
| `ContentScanner::record` | 修复**增添一个新装修模块导致其他旧模块译文失效**的问题。即使 Builder 发布版本变化，只要已有字段的英文原文不变，就更新其来源版本而不撤销旧译文 |
| `Services/StorefrontPresentationConfig.php` | 更新前台插件发布标识，以避免新版本误沿用旧脚本缓存命名空间 |
| `Tests/verify_builder_display_contract.php` | 新增可在 LONGOS PHP 环境运行的字段识别/排除回归用例；涵盖新增轮播、按钮、隐藏项、非英文本地化值和 SEO 排除 |

## 适用实例

- 现在只启用了首页的 `faq`、`trust_cards`、`shopify_slideshow`：只会扫描这几个当前可见模块，不会预翻译系统备用模块。
- 下周新增一个 `new_hero_block`，其中有 `headline`、`cta_text` 和 `description`：下一次管理员创建翻译任务时会发现这些公开文字并为启用的目标语言建立增量翻译项；**不需要为新模块手工写特定服务商适配器**。
- 修改 FAQ 的一个答案：只让受影响的原文进入重新翻译；其余未修改条目复用翻译结果。
- 删除某个营销模块：再次扫描后该模块旧字段被标记不再公开，不能继续作为新任务/新发布来源。
- 模块包含 `seo_title`、`meta_description`、`image_url`、`price`、`customer_name`：这些不是可发送给翻译服务商的公开显示字段，保留原值。

## 安全、性能和覆盖边界

- 扫描源来自 `BuilderStateService::published()`，只读取英文源，不读取后台编辑草稿或用户输入。普通商品、分类、页面和前台固定标签沿用之前的独立白名单。
- 新组件如果使用未知的、不能识别为显示文字的自定义字段名，本版不会贸然翻译所有配置字符串。应在 `unsupported_components` 报告和真实前台测试中确认后，给组件注册明确的显示字段映射。**仅凭上传的插件源码无法保证未见过的 LONGOS 主题/第三方组件 100% 无漏译**。
- 仅翻译可选取、可安全插回前台的文本。图片像素中的英文、视频内嵌字幕、CSS 伪元素内容不在本次范围。
- 递归扫描设有深度、集合项数及最大候选数限制，以免异常模块拖垮扫描；极端超大模块需专门测试和适配。
- 界面正文遵循“先翻译→质量检查→批准/安全自动发布→前台读取已发布本地词典”；不会在访问者页面上进行现场 AI 翻译。
- 现有的翻译任务取消、翻译库批量删除、服务商安全删除、SiliconFlow 双免费模型选择，以及账务与租户隔离机制均予以保留。

## 部署和验收

1. 在测试环境备份原插件、相关租户数据库、发布版本和队列，替换完整 `LongosGlobalTranslate` 目录；v1.9.1→v1.10.0 没有新数据库迁移。
2. 按 LONGOS 正式流程清理 Blade/路由缓存、更新静态资源并重启 PHP/队列 worker，确认运行版本 `v1.10.0`。
3. 在 PHP 环境运行：`php LongosGlobalTranslate/Tests/verify_builder_display_contract.php`。
4. 在 Node 环境运行：`node LongosGlobalTranslate/Tests/verify_source_contracts.mjs`。
5. 使用一个测试子站启用两个装修模块、隐藏一个模块，运行「扫描并开始」。检查任务只涉及公开且已使用的可见文本。
6. 新增、修改、隐藏、删除模块，再次运行「扫描并开始」。检查新项/变更项需要翻译；未变旧模块继续显示原有译文；移除的旧条目不在新的发布中出现。
7. 使用真实主题检查轮播、公告、图文、FAQ、嵌套富文本与第三方组件。针对漏译自定义字段，补专门的 renderer/扫描契约，而不是扩大到所有原始配置字符串。
8. 核查 `seo_title`、`meta_description` 等未被建立翻译条目；同时确认前台地址、金额、SKU 和付款信息完全未改变。

## 已完成验证与限制

已运行 Node 源码合约与后台 JavaScript 静态语法检查、ZIP 完整性检查。当前工作区没有 PHP CLI、完整 LONGOS Builder 主题渲染源码、真实租户数据和提供商测试密钥，**尚不能声称已完成所有新组件的前台端到端翻译验收**。发布前务必在测试站执行上述 PHP 验证和真实页面差异检查。
