# LONGOS Global Translate v1.9.1 — 硅基流动多免费模型

日期：2026-11-09。完整升级包：兼容此前 v1.9.0 的硅基流动 API 账户，保留所有旧版翻译库、任务与服务商删除功能。

## 为什么升级

v1.9.0 将硅基流动固定为 `tencent/Hunyuan-MT-7B`。硅基流动官网当前的价格中心还标出了其他可用于语言任务的免费模型。本版新增**可选择的免费模型列表**，但不允许从免费模型自动切换至任意收费模型。

| 选项 | 官方模型 ID | 推荐用途 |
| --- | --- | --- |
| 专用机器翻译（默认） | `tencent/Hunyuan-MT-7B` | 商品内容、页面文案、一般的多语言翻译 |
| 通用大模型翻译 | `XingChenAGI/Xing4.0-29B` | 复杂说明、较长句子或希望比较措辞风格的内容 |

两款模型都出现在本次开发时的 [硅基流动官方价格中心](https://siliconflow.cn/pricing) 免费模型范围。**价格和可用性随时可能变动，应在启用前再确认。** 有些第三方工具宣称免费使用的模型属于合作专用公益通道；它们的赠送资格不能推定为使用个人 API Key 时也免费，因此没有贸然加入名单。

## 简洁的操作流程

1. LONGOS 后台 →「全球翻译」→「API 账户」。
2. 新建硅基流动账户：输入账户标识和 API Key，在「免费翻译模型」下拉框中选一个模型，保存。
3. 老版本已有硅基流动账户：点击「编辑」，直接在下拉框选择另一款模型。**不需要再次填写原 API Key**。
4. 若模型确实变化，服务端会更新加密配置、增加凭据版本、清除旧模型验证状态并关闭派发。需要重新点击「验证账户」；成功后再「开启派发」。仅调整额度或保存同一模型不会触发此流程。
5. 为避免模型切换干扰正在发送的请求，如果该账户仍有 `reserved`、`sending` 或关联 `claimed` 的翻译任务项，服务端会拒绝切换并提示先等待结算。

## 关键实现约束

- `SiliconFlowProvider::FREE_MODELS` 是**服务端许可名单**。保存账户、模型独立切换和实际调用三层校验均会阻止其他模型 ID。
- 模型选择存放于原有加密凭据包。管理页面只能获知当前公开的**模型 ID**，不能返回或看到 API Key。
- 模型切换通过原有 `ProviderAccountService::update()` 数据库事务完成，不改计费身份、历史额度、账务尝试记录或租户权限，不增加迁移文件。
- 运行时 API 请求使用所选模型，调用端点仍为 `POST https://api.siliconflow.cn/v1/chat/completions`。
- **不会因某款模型限流或失败而自动切换其他模型**。如果需要多模型自动接力，应在真实提供商计费/限流接口和可恢复请求规则明确后单独设计，避免双重消耗与不可控调用。
- 模型的官方限速、账号权限及免费政策各不相同。插件只控制本地字符与 QPS，不能向服务商锁定零元价格。

## 版本升级

1. 先备份插件目录、全体相关租户数据库、队列及原有硅基流动 API 配置。
2. 在测试子站解压并通过现有 LONGOS/Coolify 正式流程替换整个插件目录，不要直接覆盖运行容器中的个别文件。
3. v1.9.0 → v1.9.1 **不需要新的数据库迁移**；从更早版本升级，请按原 v1.6–v1.8 文档补齐既有迁移。
4. 清理应用/Blade/路由缓存，重启 PHP 进程与队列 worker，确认后台运行版本显示 `v1.9.1`。
5. 使用测试 API Key 验证两个模型的真实翻译效果、完整响应及官方账户价格，再投入生产。

## 验收检查清单

| 用例 | 应达到的结果 |
| --- | --- |
| 新建账户并选择两个模型中的任一个 | 存储加密 API Key 与所选模型；默认不派发 |
| 原 v1.9.0 账户升级后编辑 | 当前模型自动选中 Hunyuan-MT-7B；无需重填密钥 |
| 不改模型，只改账户额度 | 原密钥、验证状态和已开启派发状态均保持不变 |
| Hunyuan → Xing4.0，仅提交新模型 | 服务端从现有加密凭据保留 API Key，重新加密配置，清除验证并关闭派发 |
| 在途请求存在时切换 | 拒绝切换，原模型和 API Key 保留 |
| 构造 API 直接提交收费模型 | 服务端拒绝；不会悄悄改为收费模型或执行实际请求 |
| 无效 Key / 429 / 空输出 / 输出截断 | 拒绝发布不完整译文、记录安全失败状态，不自动转付费模型 |
| 更换模型后完成新验证 | 翻译任务使用新模型，审核与发布链路仍正常 |
| 不同 SaaS 子站分别选择不同模型 | 各自管理自己的 API Key、额度、任务和词典，不互相污染 |
