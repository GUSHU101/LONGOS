# LONGOS Global Translate v1.8.0 — 删除翻译服务商账户

发布日期：2026-11-09  
在完整 v1.7.0 升级包上新增 API 账户删除功能；保留 v1.6.0 的翻译库批量删除、任务取消/归档，v1.6.1 的简洁后台，以及 v1.7.0 的并发、防重复计费和大库发布修复。

## 使用方法

1. 管理后台进入「全球翻译」→「API 账户」。
2. 在所需账户右侧点击红色「删除」，阅读确认窗口。
3. 确认后，后台检查未结算请求；符合安全条件时移除账户并刷新页面。

此操作删除的是**当前租户配置的某个翻译 API 服务商账户**，例如某个阿里云或 DeepL API Key。不会删除插件支持的服务商种类，也不会删除其他租户或其他账户。

## 安全行为

| 场景 | 系统处理 |
| --- | --- |
| 服务商没有在途请求 | 立即关闭账户与派发、从账户列表移除、删除加密密钥及其指纹和控制台链接 |
| 仍有 `reserved` 或 `sending` 请求 | 拒绝删除，提示先停止对应任务并等待结算；不能误判远程请求不收费 |
| 账户仍关联 `claimed` 翻译任务项 | 拒绝删除；待任务完成或进行既有的保守超时恢复后再操作 |
| 已有成功、失败或 `uncertain` 历史用量 | 保留台账、翻译请求尝试与审计，避免额度丢失和重复收费；不因为删除自动退款 |
| 账户已删除或不存在 | 返回可读错误，不修改其他账户 |
| 使用原服务商与相同计费身份重新添加 | 需要重新提供 API 密钥、重新验证和开启派发；复用历史账户/额度台账，不会获得全新免费额度。原计费时区予以保留 |

底层采用**安全归档加密钥清除**，并非物理删除 `lgt_provider_accounts` 行，因为翻译和额度历史仍引用这个账户 ID。字段 `archived_at` 对普通管理页面和派发查询隐藏旧账户。

## 更新与迁移

1. 先备份原插件、受影响的所有租户数据库与队列配置。
2. 通过 LONGOS 原有插件部署流程替换整个 `LongosGlobalTranslate` 目录。
3. 在 LONGOS/Coolify 正式升级链路执行插件迁移。新增文件：`Migrations/2026_11_09_000010_add_provider_archiving.php`；它为 `lgt_provider_accounts` 增加可空 `archived_at` 字段和索引。若跨版本直接升级，仍需按顺序完成 `000008`、`000009` 迁移。
4. 让 PHP 进程和队列 worker 载入新代码，清理页面/路由缓存，检查后台自检状态，再使用测试账户验证删除。

**不要**仅替换 Blade 页面或手工从数据库删除服务商账户行。由于之前的计费尝试还指向原账户，直接 SQL 删除会破坏追溯能力。

## 集成验收

| 编号 | 测试 | 预期 |
| --- | --- | --- |
| C1 | 新增一个未启用账户，直接删除 | 页面刷新后从账户表消失，数据库保留归档行、密钥字段为空 |
| C2 | 删除启用但没有在途请求的账户 | 禁止后续派发；其他已验证的服务商仍可使用 |
| C3 | 在 `reserved` 或 `sending` 请求进行时删除 | HTTP 422 且未删账户；请求可以继续保守结算 |
| C4 | 在已领取任务项仍引用该账户时删除 | HTTP 422；不能清掉仍被执行的密钥 |
| C5 | 删除账户后查询用量与审计 | 过往用量、账务事件和审计均未被删除，也没有自动新增可用免费额度 |
| C6 | 删除后再次以同一计费身份添加，提交新密钥 | 需要重新验证；复用原账户 ID 和台账；计费时区不被重置 |
| C7 | 无权限/无 CSRF 请求删除其他账户 | 按既有插件后台中间件拒绝请求 |
| C8 | 在两个 SaaS 租户中分别配置同名服务商，删除其一 | 仅当前租户账户被归档，另一个租户不受影响 |
