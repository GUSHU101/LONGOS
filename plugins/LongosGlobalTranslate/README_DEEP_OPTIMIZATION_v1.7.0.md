# LONGOS Global Translate v1.7.0 — 核心可靠性与性能优化

发布日期：2026-11-09  
基础版本：用户上传 v1.5.7；本升级包完整包含 v1.6.0 的数据/任务维护、v1.6.1 的后台精简，以及 v1.7.0 的深度修复。

> 这是针对**整个多租户 SaaS 翻译插件**的升级，不按手机壳或任何单一商品品类硬编码。只调整 LongosGlobalTranslate 插件，未修改支付、订单或 LONGOS 主程序。

## 1. 源码确认的问题与本次改动

| 风险与真实代码路径 | 以前的行为 | v1.7.0 处理方式 |
| --- | --- | --- |
| 不同任务范围重复派发同一条原文（`TranslationJobService::plan/claim/processItem`） | 计划时主要检查当前任务，同一条原文被“商品任务”和“全站任务”覆盖时可能同时发起 API 请求 | 计划阶段检测其他活跃任务；旧任务并发领取时通过原文行锁串行化并识别在途重复项；外发前再次检查危险计费记录 |
| 请求已发送但结算不明，或已记账但本地写入失败 | 重建其他任务时，部分历史请求可能被视为未翻译，造成再次发起调用 | 对 `sending` / `uncertain`，以及此前标记失败的 `committed` 尝试实行防重发阻断；返回 `PRIOR_BILLING_OUTCOME_UNRESOLVED`，必须人工核账，不猜测退款 |
| 任务完成与领取、取消的锁顺序相反（`finishItem/failClaimsForRun`） | 一边持有任务项锁后等任务锁，另一边先拿任务锁后等任务项锁，可能引发数据库死锁 | 统一成先锁任务、后锁任务项；保留 claim token 校验与事务计数 |
| 额度预留与结算锁顺序相反（`UsageLedger`） | `reserve` 先锁月份再查请求，`transition` 先锁请求再锁月份，重复 UUID 或并发更新存在死锁路径 | 统一为月份先于请求；`markSending` 在账户锁内依次锁月份与请求，保持状态迁移和账务事件原子性 |
| 修改 API 免费额度后本期余额不变（`ProviderAccountService`） | 新额度写到了账户配置，但已存在的 `lgt_usage_months.soft_limit` 仍使用旧值 | 更新当前计费月的 `soft_limit` 和外部用量缓冲；绝不清零已提交、已预留、发送中或不确定数量 |
| 改变计费时区导致切换月度余额记录 | 使用同一账户的不同 YYYY-MM 周期键，可能无意或故意重复获得额度 | 账户已有月度台账时禁止直接变更计费时区；保留旧账户，必要时单独配置新的计费身份 |
| 发布与回滚内存占用（`PublicationService`） | 把某语言的全部已审核译文或某次发布的全部条目一次取入 PHP，然后分块写入；商品量增大时内存暴涨 | 按 ID 分页，每批最多 250 条查询、比较、插入；同版本发布的幂等比较也分批执行 |
| 发布版本号查询对部分数据库不兼容 | 聚合 `MAX(revision)` 与 `FOR UPDATE` 组合，在某些 SQL 方言中会报错 | 先按 `revision` 降序选取并锁定真实版本行；语言级维护锁保证并发发布按顺序执行 |
| 整库删除操作不直观 | Ctrl/⌘ 多选语言不适合触摸屏，误认为只能删一种语言 | 改为可见的逐项勾选，不再要求快捷键；严格的后台确认短语、事务、源语言保护与任务互斥仍保留 |

注意：防重复机制是在应用和数据库层增加保护，**不能承诺**远程服务商完全不会出现重复计费。对不确定结果仍需对账，也没有修改服务商的付费条款。

## 2. 兼容与数据约束

- 翻译内容保留独立于商品品类的 `kind`、`field`、原文哈希和目标语言索引；不读取或发送客户地址、支付数据或订单个人信息。
- 批量删除最多 100 条/次，页面最多选择当页 25 条；按语言整库重置与删除已发布条目的功能沿用 v1.6.0 的操作确认与数据库原子性。
- 删除译文同时从各历史版本删除相应发布条目，防止回滚复活；这是“不可变发布快照”的**显式合规擦除例外**，删除前必须备份。
- 停止任务后不再领取新请求；已发出的远程 API 不能撤回。归档删除任务只隐藏任务，不抹掉用量、尝试记录和审计证据。
- 新增索引：`lgt_job_pair_state` 和 `lgt_published_translation`，用于降低跨任务查重与删除已发布译文的查询开销。
- 新增阻断错误码会在任务失败摘要中显示人工处理提示。任务运行期间不要通过数据库手工修改请求状态为“未计费”。

## 3. 安全升级步骤

1. 在测试环境备份**所有相关租户数据库**、原插件目录、发布版本和队列设置，建议选择队列空闲维护窗口。
2. 保留 `LongosGlobalTranslate` 目录名，通过 LONGOS 自身的插件发布部署流程替换完整源码，不能只上传后台页面。
3. 按现有 LONGOS/Coolify 升级链路执行各租户插件迁移（原系统文案说明为 `saas:upgrade`）；**不要在生产容器里自行临时运行 Composer 或不明迁移命令**。检查 v1.6.0 迁移 `2026_11_09_000008_add_job_archiving.php` 和新迁移 `2026_11_09_000009_add_maintenance_query_indexes.php` 均正常完成。后一迁移增加两条查询索引，不删除数据。
4. 依既有流程清理路由/视图/应用缓存、重新发布插件前端资产，并重启 PHP-FPM 与翻译队列 worker，避免旧进程继续以旧逻辑处理账务。
5. 先在一个**测试子站**执行下方 B1–B12 验收，再滚动升级其他租户。首次升级后检查后台「诊断与运行状态」、本地额度、任务状态与前台发布语言。

## 4. 部署环境验收矩阵

| 编号 | 测试操作 | 必须满足的结果 |
| --- | --- | --- |
| B1 | 新建“商品 FR”和“全站 FR”两个有重叠原文的任务，多个 worker 并发处理 | 同一 `(entry, locale, source_hash)` 不会在两个任务中同时发出 API 请求；重复项被跳过或规划期延后 |
| B2 | 手工构造旧任务的 `sending`/`uncertain` 历史记录，再规划相同原文 | 不重发对应 API；后台提示请求结果需人工核对 |
| B3 | 旧任务某请求 `committed`，但任务项是 `failed` 且没有可复用译文 | 不以“失败”作为免费重发依据；需人工核验并处理 |
| B4 | 并发执行 `reserve`、`markSending`、`commit`、`cancelJob`、`finishItem` | 无永久死锁、重复记账或任务项完成计数异常；对数据库超时/死锁保留可追踪日志 |
| B5 | 有旧月度台账后，将安全额度从 1,000 修改成 3,000 | 同周期展示新的安全上限，已用量不变；剩余额度据实计算 |
| B6 | 将当前周期额度调低到已占用量以下 | 剩余额度为 0，新请求停止；既有 committed/sending/uncertain 记录不被清空 |
| B7 | 已产生月度台账后修改计费时区 | HTTP 422，要求保留时区或采用独立计费账户；不发生新的额度周期重置 |
| B8 | 在测试库建立 10,000+ 已审核译文，连续发布两次 | 查询和插入分页；第二次内容未改动应复用既有 revision，而不是制造重复版本 |
| B9 | 修改 1 条审核译文，再发布并回滚前一版本 | 发布生成新版本，回滚恢复指定译文版本；其他记录不缺失 |
| B10 | 删除发布中的两条译文后回滚更早发布版本 | 两条删除的译文不会被回滚复活，其他条目正常；原文索引与额度不变 |
| B11 | 手机端进入「翻译与任务」→「数据清理与整库重置」，勾选 FR/DE | 可不按 Ctrl/⌘ 多选，后台仍要求精确确认；源语言不可选择 |
| B12 | 将已取消、有在途请求的任务立即删除，并用其他租户重复操作 | 在途任务不能归档；不同租户的数据、额度、发布版本绝不互相影响 |

此外需完整回归 v1.6.0 的 A1–A12 与 v1.6.1 的 UI 验收清单。对异常数据库/队列场景建议加入 Laravel 集成测试与 MySQL 并发测试，不应把静态源码检查视为压力测试。
